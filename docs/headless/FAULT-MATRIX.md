# 协议故障注入矩阵

`npm run test:faults`（等价于 `run-s test:state test:application test:conflicts test:local test:scan test:pull test:sync test:resources`）汇总可重复的合成故障注入套件。每个场景都以**持久化状态**和**完整内容摘要或逐字节比较**判定结果：发送成功、连接成功、日志或界面计数都不作为同步证据，出现未确认操作时不得报告成功。

## 发送与确认

| 注入点 | 场景 | 套件 | 判定依据 |
| --- | --- | --- | --- |
| 发送前 | 持久化写入真实失败（权限）时不得发送 | `test:state`、`test:sync` | 操作保持未确认，远端无写入，基线不变 |
| Ack 丢失 | 读回目标已存在具体发送版本 → 恢复基线，不重复发送 | `test:sync`、`test:conflicts` | 操作 acknowledged 且基线指向该发送版本；远端内容逐字节一致 |
| Ack 重复 / 错序 / 旧连接事件 | 只允许对应连接、context 与路径的确认提交 | `test:sync` | 旧事件不能提交新编辑；未确认操作保持 pending |
| 确认后本地又变 | A 的确认到达时本地已是 B | `test:sync` | 基线只记录 A；B 作为后继操作继续，不被 A 的确认吞掉 |
| 确认路径不一致 | Ack 携带其它路径 | `test:sync` | 拒绝提交并超时，状态不前进 |
| 读回内容改变 | 读回版本与发送版本不同 | `test:sync` | 保留 pending 并进入冲突，不写基线 |

## 附件会话与分片

| 注入点 | 场景 | 套件 | 判定依据 |
| --- | --- | --- | --- |
| 会话过期 | 服务端收齐全部分片但不返回 Ack；超时后重试 | `test:sync`（`expired-session`） | 第一次尝试保持 `sent`、远端无内容；第二次请求全新 `sessionId` 并从快照完整重传 |
| 取消 | 传输中取消 | `test:sync`（`cancel`） | 取消不产生半成品；重试使用新会话完整分片 |
| 分片乱序 / 重复 / 缺失 | 接收端分片到达顺序异常 | `test:pull` | 页码与内容校验通过前不推进页；缺片不落盘 |
| 分片损坏 / 内容改变 | 组装后摘要不符 | `test:pull` | 保留已有文件并报告失败 |
| 下载中断后重启 | 文件发布后应用提交前终止 | 固定服务端 `--file-pull` 探针 | 重启后重新读取远端完整版本，无遗留 `prepared` 应用 |

## 落盘与提交边界

| 注入点 | 场景 | 套件 | 判定依据 |
| --- | --- | --- | --- |
| 创建 / 替换的 8 个进程崩溃窗口 | 准备后、临时写入后、发布后、状态提交后各位置 SIGKILL | `test:application` | 恢复识别原版本、目标版本与外部修改，幂等重试，不写半文件 |
| 事务提交边界 | 提交后 SIGKILL、未提交事务 SIGKILL | `test:state` | 重开后终态一致，未提交事务不部分可见 |
| 批次 / 分页 | End 提前、缺页、重复页、检查点提交失败 | `test:pull` | 不推进安全检查点，重启后不遗漏未完成项 |
| 受控本地操作 | 删除与重命名 12 个终止/重试场景、竞争者进程 | `test:local` | 不重复删除或重命名；来源与目标身份和内容保持 |
| 冲突决策 | 决策 prepared、本地意图 prepared、文件发布、本地 applied、操作 sent、操作 acknowledged、决策 confirmed 七个 SIGKILL 位置 | `test:conflicts` | 恢复后逐字节一致；陈旧决策无副作用并产生新冲突 |
| 扫描失败 / 混合读取 | 目录读取失败、扫描中修改、事务提交失败、取消 | `test:scan` | 保留上次成功清单，不产生删除意图 |

## 身份与资源

| 注入点 | 场景 | 套件 | 判定依据 |
| --- | --- | --- | --- |
| 身份错配 | 端点、认证主体、Vault、本地目录或同路径 inode 改变 | `test:sync`（identity / runtime-identity） | 拒绝恢复旧 pending，保留文件与数据库；同主体换 token 可恢复 |
| 所有权冲突 | 第二个进程写同一 Vault 或状态目录 | `test:filesystem`、`test:local` | 后者拒绝启动，不产生并发写入 |
| 资源上限 | 共享/重启配额、残留发布别名、磁盘写失败、扫描边界 | `test:resources` | 保留内容并报告阻塞，不清理未解决快照，不误报成功 |
| 只读门禁 | 只读模式下出现上传请求 | `test:pull` | 发送白名单拦截业务写入，服务端请求记录中没有上传 |

## 维护方式

新增协议或状态机行为时必须同时加入本矩阵对应的失败场景，并给出持久化状态与完整内容判定；只断言“调用返回”不算覆盖。固定服务端探针只验证替身没有虚构能力，不能替代本矩阵中的进程级故障注入。
